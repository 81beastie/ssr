# ssr

**ssr** (secret scrub & replace) — утилита командной строки, которая находит секреты в тексте (токены, пароли, ключи), заменяет их на плейсхолдеры и кладёт результат в буфер обмена.

Идея: ты хочешь поделиться конфигом или логом — но в них пароли и токены. Вместо ручного вычищения:

```bash
cat app.conf | ssr
# Ctrl+V → все секреты уже заменены на <ssr token>, <ssr password>
```

## Возможности

- 🔍 **Секреты «из коробки»**: JWT, GitHub-токены (`ghp_`, новый `github_pat_`), AWS-ключи (`AKIA`), Bearer-токены, хэши теневых файлов (`$y$`, `$6$`, bcrypt), `password=`/`pwd:`/`pswd:`/`pass:`, `token=`/`token:` (любой регистр, `=` и `:`), `*_SECRET=`/`*_TOKEN=`, `логин:пароль@хост` (со схемой и без)
- 📋 **Буфер обмена из коробки**: X11, Wayland, Windows, macOS, OSC 52 (SSH)
- 🔢 **Умные плейсхолдеры**: одинаковые секреты → одинаковые плейсхолдеры, разные — нумеруются (`<ssr token:1>`, `<ssr token:2>`)
- 👻 **Самоубийственный демон на Linux**: держит буфер и умирает, как только ты скопируешь что-то другое — никаких висящих процессов
- ⏱️ **`--timeout`**: секрет гарантированно исчезнет из буфера через N минут
- 📁 **Файловые режимы**: `-f` чтение из файла, `-o` запись в файл
- 🇷🇺 Справка на русском: `ssr --help`

## Установка

### Из исходников (нужен Go 1.21+)

```bash
go install github.com/81beastie/ssr/cmd/ssr@latest
```

### Сборка из репозитория

```bash
git clone https://github.com/81beastie/ssr
cd ssr
go build -o ssr ./cmd/ssr
```

### Кросс-компиляция

```bash
GOOS=windows GOARCH=amd64 go build -o ssr.exe ./cmd/ssr
GOOS=darwin  GOARCH=arm64 go build -o ssr-macos ./cmd/ssr
```

## Использование

```bash
# stdin → буфер обмена (главный сценарий)
cat app.conf | ssr

# stdin → stdout (буфер не трогаем)
cat app.conf | ssr -s > clean.conf

# файл → буфер
ssr -f app.conf

# файл → файл рядом (app.conf.ssr)
ssr -f app.conf -o .ssr

# файл → указанный файл
ssr -f app.conf -o clean.conf

# посмотреть, что найдено, без замены
cat app.conf | ssr -n

# буфер умрёт через 5 минут (страховка для секретов)
cat app.conf | ssr -t 5m

# принудительный бэкенд (например, через SSH)
ssh server "cat app.conf" | ssr -b osc52
```

## Флаги

| Флаг | Полный | Описание |
|---|---|---|
| `-f` | `--file` | читать текст из файла вместо stdin |
| `-o` | `--out` | записать результат в файл (`.ssr` — рядом с исходным) |
| `-s` | `--stdout` | вывести очищенный текст в stdout, не трогая буфер |
| `-n` | `--dry-run` | отчёт о найденных секретах, ничего не менять |
| `-b` | `--backend` | принудительный бэкенд: `x11`, `wayland`, `win32`, `mac`, `osc52` |
| `-t` | `--timeout` | максимальное время жизни демона-держателя буфера (напр. `5m`) |
| `-v` | `--version` | версия |
| `-h` | `--help` | справка (на русском) |

## Пример

```bash
$ echo 'db_password=hunter2
GITHUB_TOKEN=ghp_16C7e42F292c6912E7710c838347Ae178B4a
postgres://admin:s3cret@db.example.com/app' | ssr -s

db_password=<ssr password>
GITHUB_TOKEN=<ssr token:1>
postgres://admin:<ssr password>@db.example.com/app
```

## Как это работает

### Плейсхолдеры

- `<ssr token>` — единственный секрет этого типа в тексте
- `<ssr token:1>`, `<ssr token:2>` — несколько разных секретов одного типа нумеруются
- одинаковые значения получают одинаковый плейсхолдер (дедупликация)

### Буфер обмена по платформам

| Платформа | Механизм | Демон |
|---|---|---|
| Linux + X11/Wayland | [golang.design/x/clipboard](https://golang.design/x/clipboard) | да — держит буфер, умирает при перехвате владения |
| Windows | системный API (библиотека) | нет |
| macOS | NSPasteboard (библиотека) | нет |
| SSH / терминал | OSC 52 escape-последовательность | нет (буфер держит терминал) |

**Почему демон на Linux?** В X11/Wayland буфер обмена — это не «хранилище», а обещание живого процесса отдать текст по запросу. Если `ssr` просто скопирует и выйдет — буфер умрёт вместе с процессом. Поэтому `ssr` порождает фонового держателя, который:
- живёт, пока никто другой не скопировал (событие SelectionClear — демон умирает сам)
- умирает по `--timeout`, если указан
- не оставляет зомби (init подчищает осиротевших)

На Windows и macOS буфер системный — процесс завершается сразу.

### OSC 52 (SSH-сценарий)

Без X11 (headless-сервер, SSH) `ssr` может использовать escape-последовательность OSC 52: терминал на **твоей локальной машине** получает её через SSH-трубу и кладёт текст в **твой локальный** буфер. Работает в kitty, WezTerm, iTerm2, Windows Terminal, alacritty (с настройкой).

```bash
ssh server "cat app.conf" | ssr -b osc52
# Ctrl+V работает на твоей машине, хотя ты на сервере
```

## Разработка

```bash
go test ./...          # все тесты (юнит + интеграционные на Xvfb)
go test ./cmd/ssr/ -v  # CLI как чёрный ящик
```

Интеграционные тесты X11 требуют `Xvfb` и `xclip` — без них автоматически скипаются.

### Структура

```
cmd/ssr/            CLI: флаги, режимы, --serve (демон)
internal/detector/  поиск секретов (regex-правила)
internal/replacer/  замена на плейсхолдеры, нумерация, дедупликация
internal/pipeline/  конвейер detect → replace → copy
internal/clipboard/ фабрика бэкендов: x11/wayland/win32/mac/osc52
internal/daemon/    держатель буфера для Linux (re-exec, SelectionClear)
```

Разработка ведётся по строгому TDD (RED → GREEN → REFACTOR).
